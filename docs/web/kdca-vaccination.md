# 질병관리청 예방접종도우미 분석

> 유형: 국가 예방접종 정보·기록·기관 연결  
> 운영: 질병관리청  
> 조사일: 2026-11-08  
> 공식: https://nip.kdca.go.kr/

# 1. 왜 육아 시스템의 핵심인가

수유/수면은 자주 하지만 놓쳐도 대개 다시 기록할 수 있다.

예방접종은:
- 시기가 있음
- 차수가 있음
- 백신별 규칙이 다름
- 국가 지원 여부가 바뀔 수 있음
- 지연 접종은 일정이 달라질 수 있음

따라서 단순 체크리스트보다 **authoritative schedule system**이 필요하다.

---

# 2. 2026년 국가예방접종사업에서 확인할 점

질병관리청은 2026년 기준 12세 이하 어린이를 대상으로 국가예방접종 지원사업을 운영하며 공식 페이지에서 지원 백신과 조건을 안내한다.

중요한 것은 구체적인 숫자를 앱에 영구 하드코딩하는 것이 아니다.

정책과 기준은 변할 수 있으므로:

```
공식 기준 버전
+
마지막 업데이트 날짜
+
원문 링크
```

가 필요하다.

---

# 3. 데이터 구조

## Schedule Definition
- vaccine code
- dose
- recommended timing/window
- eligibility
- source version

## Actual Record
- administered_at
- dose
- institution
- vaccine/product if available

둘을 분리한다.

---

# 4. 좋은 알림 시스템

나쁜 방식:
> 내일 예방접종!

좋은 방식:
```
다음 접종 가능 기간이 시작됩니다.
백신: ...
차수: ...
공식 일정 확인
[접종했어요]
[병원 찾기]
[나중에]
```

완료 여부는 사용자가 확인하거나 공식 기록과 연계된 경우에만 바뀌어야 한다.

---

# 5. 계절성 예방접종

인플루엔자처럼 매년 사업기간이 바뀌는 항목은 일반 고정 예방접종과 분리해야 한다.

2026~2027절기 어린이 인플루엔자 사업도 대상 연령과 사업기간이 별도로 고지된다.

즉 스케줄 엔진에는:
- birth-based schedule
- seasonal campaign

두 종류가 필요하다.

---

# 6. 지연 접종

일부 백신은 접종시기가 지연되면 횟수/일정이 달라질 수 있으며 질병관리청도 세부 일정은 예진의사와 상담하도록 안내한다.

따라서 앱이 임의로:
> 놓쳤으니 7일 뒤 맞으세요

라고 재계산하면 안 된다.

더 안전한 UX:
> 예정 기간을 지났습니다. 공식 일정 및 의료진에게 따라잡기 접종 일정을 확인하세요.

---

# 7. 병원 연결

좋은 예방접종 기능은 달력에서 끝나지 않는다.

```
예정
→ 위탁의료기관 찾기
→ 방문
→ 실제 기록
→ 다음 일정
```

이것이 완전한 loop다.

---

# 8. 가져올 패턴

## Source-versioned Schedule
일정 정의에 출처와 업데이트 버전을 붙인다.

## Actual vs Planned
예정과 완료를 절대 같은 필드로 쓰지 않는다.

## Official Deep Link
상세 조건은 공식 원문으로 빠르게 이동.

## Expiring Reminder
하루 전 알림보다 **접종 가능 기간 시작/종료**가 더 중요할 수 있다.

---

# 9. 제품 안전 원칙

1. 사용자의 생년월일만으로 의료적 예외를 모두 처리하려 하지 않는다.
2. 지연/기저질환/특수상황은 의료진 확인으로 넘긴다.
3. 정책 업데이트가 필요한 기능은 서버에서 최신화한다.
4. 공식 출처 날짜를 표시한다.
5. '완료'를 자동 추정하지 않는다.
