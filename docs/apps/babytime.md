# 1. 한 문장 정의

BabyTime은 **아기의 하루를 빠르게 기록하고, 여러 양육자가 같은 상태를 공유하며, 누적 기록을 패턴과 통계로 다시 보여주는 생활 이벤트 중심 육아 기록 시스템**이다.

---

# 2. 핵심 사용자 문제

신생아기 부모의 문제는 '육아 정보를 모른다'보다도 아래와 같은 **기억 부담**에 가깝다.

- 마지막 수유가 몇 시였는지 기억하기 어렵다.
- 방금 기저귀를 누가 갈았는지 모른다.
- 아이가 오늘 얼마나 잤는지 체감하기 어렵다.
- 부부가 교대하면 현재 상태를 다시 설명해야 한다.
- 며칠 동안의 패턴이 좋아졌는지 나빠졌는지 기억에 의존하게 된다.

BabyTime의 핵심은 이 문제를 **기록 → 동기화 → 시각화**로 해결하는 데 있다.

---

# 3. 주요 기록 범위

공식 App Store 설명에서 확인되는 주요 기록은 다음과 같다.

- 모유 수유
- 젖병 수유
- 수면
- 기저귀
- 터미타임
- 유축
- 성장
  - 키
  - 몸무게
  - 머리둘레
- 증상
- 진료
- 발달 마일스톤
- 사진·특별한 순간

타이머는 수유·유축·수면 등에 사용된다.

이 구성이 중요한 이유는 **신생아기의 고빈도 반복 이벤트와 저빈도 장기 이벤트를 한 앱 안에 같이 담는다**는 점이다.

---

# 4. 핵심 사용자 흐름

## 반복 사용 루프

```
홈
→ 활동 선택
→ 현재시각 기준 빠른 기록
→ 최근 활동 상태 갱신
→ 다른 양육자에게 동기화
→ 하루/주간/월간 차트
→ 패턴 확인
```

핵심은 기록 완료 자체가 아니라 **다음번 앱을 열었을 때 이전 기록이 기억을 대신한다**는 것이다.

---

# 5. BabyTime이 잘하는 구조

## 5.1 최소 터치 기록

공식 웹은 '최소한의 터치'를 핵심 가치로 명시한다.

이것은 육아 앱에서 매우 중요하다.

일반 생산성 앱은 사용자가 화면을 보고 입력할 여유가 있다는 전제가 있지만, 육아 기록은 다음 상황에서 일어난다.

- 아이를 안고 있음
- 수유 중
- 불을 끈 야간
- 한 손만 사용 가능
- 기록을 빨리 끝내고 다시 아이에게 집중해야 함

따라서 **기록 속도 자체가 제품의 핵심 기능**이다.

---

## 5.2 실시간 공동양육

공식 웹에서는 엄마·아빠·가족·베이비시터가 함께 기록할 수 있고 실시간 동기화를 지원한다고 설명한다.

이 구조는 매우 중요하다.

나쁜 구조:
```
엄마 계정
└─ 아빠에게 일부 정보 공유
```

더 좋은 구조:
```
Baby
├─ 엄마
├─ 아빠
├─ 조부모
└─ 베이비시터
```

즉, 데이터의 주체가 **특정 보호자가 아니라 아기**가 된다.

---

# 6. 데이터 가치 변환 단계

BabyTime은 대략 아래 단계까지 올라간다.

```
활동 기록
↓
시간순 기록
↓
일/주/월 통계
↓
생활 패턴 시각화
↓
기간별 비교
```

공식 웹은 복잡한 생활 패턴을 시각화하고 기간별 활동 기록을 비교한다고 설명한다.

이 지점이 일반 메모앱과의 핵심 차이다.

---

# 7. 시각화에서 배울 점

BabyTime의 강점은 기록 자체보다 **'패턴 비주얼라이징'을 제품 가치로 전면에 내세운 것**이다.

육아 기록은 숫자 표보다 다음 표현이 더 유용하다.

- 하루 타임라인
- 수면 블록
- 수유 간격
- 반복되는 시간대
- 주간 비교
- 성장 추세

중요한 것은 '정확한 통계'보다 **부모가 3초 안에 이해하는 시각화**다.

---

# 8. 성장 기록

키·체중·머리둘레를 성장차트로 보는 구조는 고빈도 이벤트와 다른 가치가 있다.

- 수유/수면: 당장 오늘의 판단
- 성장: 장기간의 추세

따라서 같은 홈에 모두 동일한 비중으로 놓기보다 **오늘 화면과 성장 화면을 분리**하는 것이 자연스럽다.

---

# 9. 사진·일기·공개 일기

BabyTime은 생활 기록 앱이지만 사진·특별한 순간·일기 공유 기능도 포함한다.

이 기능은 데이터 기록이 너무 기계적인 경험이 되는 것을 완화한다.

그러나 구조적으로는 주의할 점도 있다.

- 건강·생활 데이터
- 가족 추억 데이터
- 공개 커뮤니티 데이터

이 세 종류는 개인정보 민감도가 매우 다르다.

따라서 제품 설계 시 공유 범위를 통합하면 안 된다.

---

# 10. 강점

## A. 매우 명확한 중심 행동
'기록한다'가 서비스의 중심에서 흔들리지 않는다.

## B. 고빈도 활동에 적합
수유·수면·기저귀처럼 하루에 여러 번 일어나는 행동에 강하다.

## C. 공동양육 가치가 즉각적
혼자 기록할 때보다 두 명 이상이 쓸 때 가치가 급격히 커진다.

## D. 원자료를 시각화로 되돌려준다
입력 노동이 단순 보관으로 끝나지 않는다.

## E. 신생아기에 특히 강한 제품 구조
신생아기의 '언제 했지?' 문제를 정확히 겨냥한다.

---

# 11. 한계와 리스크

## A. 기록 피로
기록 카테고리가 많아질수록 사용자는 '좋은 부모가 되려면 다 기록해야 한다'는 압박을 받을 수 있다.

### 개선 방향
월령과 사용패턴에 따라 자주 쓰는 항목만 홈에 남기고 나머지는 숨긴다.

---

## B. 분석과 의료 판단의 경계
생활 패턴 비교는 유용하지만 성장·증상 등의 데이터가 '정상/비정상'을 과도하게 판정하는 UX로 넘어가면 위험하다.

---

## C. 월령이 올라갈수록 핵심 가치 변화
신생아기에는 기록 빈도가 높지만 아이가 커지면 모든 수유·기저귀를 계속 기록하지 않는다.

따라서 장기 유지에는 다음이 필요하다.

- 이유식
- 발달
- 놀이
- 검진
- 추억
- 생활습관

즉 **기록 앱에서 성장 동반 앱으로 전환**해야 한다.

---

# 12. 가장 가져올 가치가 큰 패턴

## Pattern 1 — Last Event First
홈에서 통계보다 먼저 보여줄 것:

```
마지막 수유 · 2시간 10분 전
현재 수면 · 38분째
마지막 기저귀 · 45분 전
```

---

## Pattern 2 — One Tap + Optional Detail

기본:
```
[소변] [대변] [둘 다]
```

필요한 경우:
```
상세 기록 펼치기
```

---

## Pattern 3 — Caregiver Handoff Card

교대 양육자가 앱을 열었을 때 설명 없이 이해해야 한다.

```
지금 상태
- 01:40 분유 110ml
- 02:05 기저귀 소변
- 02:28 잠듦
```

---

## Pattern 4 — Timeline First, Statistics Second

부모는 처음부터 평균값보다 '오늘 무슨 일이 있었나'를 먼저 본다.

---

# 13. 아기 양육 시스템에 주는 시사점

BabyTime에서 가장 중요한 교훈은 **많이 기록하는 것이 아니라 기록 순간의 마찰을 극단적으로 낮추는 것**이다.

신생아기 홈은 다음 정도면 충분할 수 있다.

```
[수유] [수면] [기저귀] [+]
------------------------
현재 수면  42분째
마지막 수유 2시간 11분 전
오늘 수유 7회
오늘 기저귀 6회
```

상세 통계는 두 번째 화면이어야 한다.

# 결론

BabyTime은 육아 기록 서비스를 설계할 때 가장 먼저 봐야 할 기준점이다.

핵심은 기능 수가 아니라:

**초저마찰 입력 → 실시간 공동양육 → 현재상태 확인 → 패턴 시각화**

이 네 단계가 하나의 루프로 잘 연결되어 있다는 점이다.
