# 1. 한 문장 정의

Napper는 **아기의 실제 수면 기록을 바탕으로 다음 낮잠·취침 시간을 예측하고, 부모가 하루를 조직하기 쉽게 만드는 수면 특화 시스템**이다.

---

# 2. 왜 분석할 가치가 큰가

범용 육아 앱은 많은 문제를 얕게 해결한다.

Napper는 반대로:
- 수면 기록
- wake window
- 다음 낮잠 예측
- 취침 계획
- 수면 추세
- 수면 교육

에 집중한다.

이런 **Vertical depth**는 중요한 제품 전략이다.

---

# 3. 핵심 문제

부모는 단순히 "몇 시간 잤는가"만 궁금한 것이 아니다.

더 실제적인 질문:
- 지금 재워야 하나?
- 아직 더 놀아도 되나?
- 오늘 낮잠이 짧았으니 다음 수면은 언제인가?
- 낮잠이 3회에서 2회로 넘어가는 시기인가?
- 오늘 외출 일정은 언제 잡아야 하나?

Napper는 수면 로그를 **하루 일정 계획 도구**로 바꾼다.

---

# 4. 핵심 루프

```
수면 기록
→ 현재 wake window 계산
→ 다음 낮잠 예상
→ 사전 알림
→ 실제 수면 기록
→ 다음 예측 보정
```

이 구조에서 기록은 과거 보관이 아니라 **예측 모델의 입력**이다.

---

# 5. 개인화된 일정

공식 페이지는 age-based schedule과 personalized analysis를 모두 제공한다고 설명한다.

이 둘은 반드시 구분해야 한다.

## age-based
```
5개월 평균 수면 패턴
```

## personalized
```
이 아이의 실제 오늘·최근 기록
```

좋은 제품은 일반 기준으로 시작하고, 충분한 개인 데이터가 쌓이면 개인화 비중을 늘린다.

---

# 6. 예측 UI에서 중요한 점

수면 예측은 확정시간처럼 보이면 위험하다.

좋은 표시 예:
```
다음 낮잠 예상
14:20~14:45

오늘 기록을 기준으로 계산했어요.
```

나쁜 표시:
```
14:31에 재우세요.
```

아기 수면은 변동성이 크기 때문에 **range + confidence + 근거**가 적합하다.

---

# 7. 알림의 가치

Napper 사용자 후기에서 반복적으로 등장하는 가치는 '30분 전 알려줘 준비할 수 있다'는 점이다.

제품 관점에서는:

```
예측
→ 준비시간 확보
→ 기저귀/수유/수면루틴
→ 더 부드러운 전환
```

즉 알림이 단순 리텐션 푸시가 아니라 **행동 준비 장치**다.

---

# 8. 수면 전문 서비스가 주는 교훈

범용 앱의 수면 탭:
- 시작
- 종료
- 합계

전문 앱:
- 기록
- wake window
- 추세
- 예측
- 루틴
- 교육
- 전환기 대응

같은 데이터 타입도 깊이가 크게 다르다.

---

# 9. 강점

- 목적이 매우 선명함
- 기록 데이터의 활용 목적이 명확함
- 예측이 부모의 하루 계획으로 연결됨
- 아이가 성장하며 낮잠 구조가 바뀌는 상황에 적합
- 통계보다 '다음 행동'을 앞세움

---

# 10. 약점과 리스크

## 예측 의존
부모가 졸림 신호보다 앱 시간을 더 신뢰할 수 있다.

## 입력 누락
수면 기록을 놓치면 예측 품질이 흔들릴 수 있다.

## 정상 변동성
성장 급등기, 질병, 여행 등에서 기존 패턴이 쉽게 깨진다.

## 수면 불안
수면 데이터가 지나치게 세밀하면 부모가 매일의 작은 변화까지 문제로 받아들일 수 있다.

---

# 11. 가져올 패턴

## Adaptive Prediction
실제 기록에 따라 다음 예측을 계속 수정한다.

## Preparation Alert
이벤트 시각이 아니라 **준비를 시작할 시각**을 알려준다.

## Domain Depth
범용 기능 하나를 깊게 파면 별도 구독 제품이 될 수 있다.

## Exception Mode
질병/여행/시간대 변화처럼 평소와 다른 날은 예측 모델에서 별도 처리할 필요가 있다.

---

# 12. 통합 육아 시스템에 적용한다면

수면 카드 예:

```
다음 낮잠
약 45분 뒤

13:50부터 준비 권장
최근 3일보다 오늘 첫 낮잠이 22분 짧았어요.

[잠들었어요]
[예측 무시]
```

사용자가 '예측 무시'를 누르는 것도 학습 데이터가 될 수 있다.

# 결론

Napper의 핵심 교훈은 **기록을 일정 예측으로 바꾸는 것**이다.

수면 영역에서는 '어제 얼마나 잤나'보다 **오늘 다음에 언제 준비해야 하나**가 더 강한 사용자 가치가 될 수 있다.
