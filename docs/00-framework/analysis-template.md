# 앱·웹 심층 분석 템플릿

> 모든 서비스는 동일한 틀로 분석하여 비교 가능성을 유지한다.

# 0. Evidence Card

- 서비스:
- 유형:
- 운영 주체:
- 주요 국가/언어:
- 대상 연령:
- 조사일:
- 공식 웹:
- 주요 근거:
- 직접 확인 가능한 범위:
- 확인하지 못한 범위:

## 근거 신뢰도

- **A — 공식/1차 자료:** 공식 웹사이트, 공식 도움말, 정부기관, 논문
- **B — 공식 앱스토어/회사 자료:** 앱 설명, 보도자료, 회사 소개
- **C — 제3자 리뷰/기사:** 제품 사용 맥락 보완
- **D — 사용자 후기:** 마찰·불편 발견에 유용하지만 사실 검증 필요

기능 사실을 C/D만으로 확정하지 않는다.

# 1. 한 문장 정의

이 서비스는 **누구의 어떤 불확실성/반복업무를 어떤 데이터와 인터랙션으로 줄이는가?**

# 2. 핵심 사용자와 상황

- 1차 사용자
- 2차 사용자
- 아이 연령
- 가장 자주 열게 되는 상황
- 사용자의 피로/인지 상태
- 경쟁 수단: 메모, 카톡, 사진첩, 검색, 병원 수첩 등

# 3. Jobs To Be Done

예:

> 새벽 3시에 수유한 뒤, 내가 시간을 기억하려고 애쓰지 않아도 다음 양육자가 마지막 수유 상태를 바로 알 수 있게 하고 싶다.

기능명이 아니라 사용자 목적 형태로 쓴다.

# 4. 사용자 여정

## 첫 사용
가입 → 아이 등록 → 기본정보 → 권한 → 첫 기록 → 첫 가치 경험

## 반복 사용
트리거 → 입력 → 결과 → 다음 행동 → 재방문

## 장기 사용
신생아 → 영아 → 이유식 → 유아기로 넘어갈 때 서비스가 어떻게 변하는가?

# 5. 정보구조

- 홈
- 기록
- 통계
- 일정
- 콘텐츠
- 커뮤니티
- 가족
- 설정

메뉴 구조보다 **무엇을 홈에 노출하는지**를 특히 본다.

# 7. 데이터 모델

### 원자료
사용자가 직접 입력하거나 기기에서 측정된 데이터.

### 파생 데이터
합계, 평균, 간격, 패턴, 성장곡선 등.

### 추론/예측
다음 낮잠 시각, 추천 활동 등.

세 종류를 반드시 구분한다.

# 8. 기록 → 가치 변환

```
Raw event
↓
Timeline
↓
Summary
↓
Pattern
↓
Interpretation
↓
Recommendation
↓
Action
```

서비스가 어느 단계까지 가는지 표시한다.

# 9. 대시보드·시각화

- 지금 상태
- 오늘
- 최근 24시간
- 주간
- 월간
- 성장 전체
- 이상 변화
- 부모에게 의미 있는 비교인가?
- 숫자가 과도하게 불안을 만들지는 않는가?

# 10. 알림 시스템

알림을 유형별로 분해한다.

- 마감이 있는 의료/검진 일정
- 반복 루틴
- 예측 기반 알림
- 콘텐츠 추천
- 커뮤니티/마케팅
- 가족 활동

알림이 **사용자 가치**인지 **서비스 재방문 유도**인지 구분한다.

# 11. 공동양육

- 계정 구조
- 아이 중심 공유 여부
- 권한 레벨
- 실시간 동기화
- 수정 충돌
- 활동 작성자
- 관리자/멤버
- 초대/회수
- 사진/건강정보 권한 분리

# 12. 개인화

- 월령
- 실제 기록
- 발달 관찰
- 사용자 선호
- 지역/국가
- AI/추천
- 개인화가 설명 가능한가?

# 13. 건강·안전 가드레일

- 정보 출처
- 최신성 표시
- 의료 진단과 일반정보 구분
- 위험 신호 안내
- 응급 연결
- 전문가 상담
- 사용자 입력 오류 가능성
- 데이터 부족 시 표현

# 14. 개인정보와 아동 데이터

확인할 것:
- 필요한 최소 개인정보
- 아이 사진
- 건강 데이터
- 광고 타겟팅 가능성
- 삭제/내보내기
- 가족 공개범위
- 외부 공유
- 위치정보
- AI 입력 데이터

# 15. 수익모델

- 무료
- 구독
- 광고
- 쇼핑/커머스
- 의료기관/B2B
- 포토북/실물
- 컨설팅
- 데이터 기반 업셀

**무료 기능이 유입을 만들고, 어떤 불안/편의가 결제로 전환되는지** 분석한다.

# 16. 잘한 점

단순 칭찬 금지.

`설계 → 사용자 문제 → 효과` 형식으로 쓴다.

예:
> 마지막 기록을 홈 상단에 고정 → 기억 의존을 제거 → 공동양육 인수인계 비용을 줄인다.

# 17. 약점과 리스크

- 기록 피로
- 과도한 알림
- 불안 자극
- 기능 비대화
- 광고/쇼핑 혼재
- 추천의 불투명성
- 국가별 의료 지침 차이
- 데이터 잠금
- 가족 권한 문제

# 18. 가져올 수 있는 패턴

특정 앱 UI를 복제하지 말고 일반화한다.

예:
- One-tap event logging
- Caregiver handoff card
- Age-adaptive dashboard
- Evidence-linked advice
- Progressive detail
- Doctor-ready summary

# 19. 그대로 가져오면 안 되는 것

브랜드/문구/시각 디자인뿐 아니라, 해당 서비스의 비즈니스 맥락에서만 성립하는 기능도 구분한다.

# 20. 제품 가설

분석 후 반드시 가설을 남긴다.

예:
> 수유·수면·기저귀 각각의 상세 통계보다, 홈에서 '마지막 행동 + 경과 시간'을 명확히 보여주는 것이 신생아기 재방문에 더 중요할 것이다.

# 21. 추가 검증할 질문

직접 앱을 설치하거나 실제 사용자 데이터를 넣어봐야 답할 수 있는 항목을 별도 분리한다.
