# 아기 양육 요구 지도

> 목적: 출생 직후부터 유아기까지 부모가 반복적으로 수행하는 **확인·기록·판단·공유·행동**을 제품 관점에서 구조화한다.  
> 검토 기준일: 2026-11-08

## 1. 핵심 관점

육아 앱의 핵심은 '기록 항목의 개수'가 아니다.

좋은 시스템은 다음 루프를 짧게 만든다.

```
아기에게 사건 발생
→ 최소 입력
→ 현재 상태 갱신
→ 패턴/이상 변화 탐지
→ 부모가 이해할 수 있게 설명
→ 다음 행동 또는 일정 제안
→ 다른 양육자와 동기화
→ 필요 시 의료전문가에게 요약 전달
```

따라서 요구를 네 층으로 나눈다.

1. **Information** — 지금 알아야 하는 것
2. **Record** — 나중에 기억·비교·전달하기 위해 남길 것
3. **System** — 기록을 자동으로 계산·연결·알림할 것
4. **Action** — 부모가 실제로 다음에 할 것

# 2. 양육 핵심 영역

## A. 수유

### 부모가 알고 싶은 것
- 마지막 수유가 언제였는가
- 모유/분유/혼합 중 무엇을 얼마나 먹었는가
- 한쪽/양쪽 수유 여부와 수유 시간
- 평소 대비 섭취량이나 간격이 크게 달라졌는가
- 분유 제조·보관 등 안전 정보
- 이유식 전환 시점 이후 우유/고형식과의 관계

### 기록 후보
- 시작·종료 시각
- 수유 유형
- 모유 좌/우 및 지속시간
- 젖병 용량
- 분유/유축모유
- 유축량
- 메모: 토함, 거부, 특이 반응

### 시스템이 계산할 것
- 마지막 수유 후 경과시간
- 24시간 총 횟수/총량
- 평균 간격
- 시간대별 패턴
- 수면과 수유의 관계

### UX 원칙
수유 중에는 두 손이 자유롭지 않다. **한 손 + 잠금화면/위젯 + 큰 타깃 + 자동 현재시각**이 중요하다.

---

## B. 수면

### 기록 후보
- 잠든 시각
- 깬 시각
- 낮잠/밤잠
- 잠든 장소
- 필요 시 야간 각성
- 선택: 잠들기 전 루틴, 수면 보조

### 파생 정보
- 하루 총 수면시간
- 낮/밤 수면 비율
- 낮잠 횟수와 평균 길이
- 깨어있는 시간
- 일정 변화

### 중요한 구분
수면 앱의 '예측'은 의료적 판단이 아니다. 제품은 예측 정확도를 확정적 사실처럼 표현하면 안 된다.

### 안전 정보
AAP는 건강한 영아를 낮잠과 밤잠 모두 **등을 대고 눕혀 재우는 것**을 권고한다. 안전한 수면 환경에 대한 정보는 단순 수면 최적화보다 우선순위가 높다.

참고: https://www.healthychildren.org/English/ages-stages/baby/sleep/pages/Where-We-Stand-Back-To-Sleep.aspx

---

## C. 배변·기저귀

### 기록 후보
- 소변
- 대변
- 둘 다
- 시간
- 선택: 색/형태/양/특이사항

### 가치
단독으로는 단순 로그지만 수유·컨디션·질병과 함께 볼 때 의미가 커진다.

### UX 주의
평소에는 '소변/대변' 한 번 탭이면 충분해야 한다. 상세 정보는 **이상할 때만 펼치는 progressive disclosure**가 적합하다.

## D. 성장

### 기록
- 체중
- 신장
- 머리둘레
- 측정일
- 측정 장소/방법

### 시스템
- 성장곡선
- 이전 측정 대비 변화
- 월령 기준 추세
- 병원 측정값과 가정 측정값 구분

### 핵심 원칙
한 번의 수치보다 **추세**를 보여주는 것이 중요하다. 대한민국 국가건강정보포털도 영유아 성장에서 현재 값 하나보다 성장곡선의 추세가 중요함을 안내한다.

참고: https://health.kdca.go.kr/

## E. 예방접종

### 시스템 요구
- 생년월일 기반 접종 일정
- 접종 완료 기록
- 다음 접종 예정
- 지연/추가 접종 시 임의 계산보다 공식 기준 확인 유도
- 의료기관 찾기
- 접종명과 차수 표시
- 계절성 접종 별도 처리

대한민국 국가예방접종사업은 지원 백신과 연령·일정이 변경될 수 있으므로 앱 내부에 영구 고정된 일정표만 두기보다 질병관리청 데이터/공식 링크를 우선해야 한다.

공식: https://nip.kdca.go.kr/

## F. 영유아 건강검진·진료

### 기록 후보
- 검진 예정일/기간
- 실제 방문일
- 신체계측
- 의사에게 물어볼 질문
- 진료 후 안내사항
- 다음 추적 일정

### 시스템 가치
평소 기록을 **진료용 요약**으로 바꾸는 기능의 가치가 크다.

예:
- 최근 7일 수유
- 최근 7일 수면
- 최근 배변 변화
- 최근 체온
- 최근 약 복용
- 성장 측정값
- 부모가 체크한 발달 우려
- 질문 목록

국내 영유아 건강검진은 생후 14~71개월에 걸쳐 운영되며 발달선별검사(K-DST)도 포함한다.

참고:
- https://www.nhis.or.kr/
- https://health.kdca.go.kr/

## G. 체온·증상·질병

### 기록 후보
- 체온
- 측정 시간
- 측정 부위/방법
- 증상
- 수분 섭취
- 수유량 변화
- 소변 횟수 변화
- 의료기관 방문
- 진단명은 사용자가 받은 진단을 그대로 기록
- 처방/안내

### 제품 안전
이 영역은 고위험이다.

앱이 해야 할 일:
- 관찰 기록
- 시간순 요약
- 공식 응급 기준 노출
- 의료기관/상담 연결

앱이 피해야 할 일:
- 불완전한 데이터로 확정 진단
- 위험 신호를 일반적인 육아 팁 아래 묻기
- 사용자가 입력한 체온 등 수치를 임의로 정상 처리

## I. 이유식·음식·알레르기 노출

### 기록
- 음식
- 최초 노출일
- 제공 형태
- 섭취 정도
- 반응
- 좋아함/싫어함
- 알레르기 의심 반응
- 재노출

### 시스템
- 먹어본 음식 목록

## J. 발달 마일스톤

### 영역
- 대근육
- 소근육/운동
- 언어·의사소통
- 인지
- 사회·정서
- 감각
- 일상생활

### 나쁜 설계
`못함 = 늦음`으로 즉시 해석하는 시스템.

### 좋은 설계

# 3. 월령에 따라 달라지는 우선순위

| 단계 | 홈에서 가장 중요한 것 |
|---|---|
| 출생~4주 | 수유, 수면, 기저귀, 체온/증상, 병원 일정 |
| 1~3개월 | 수유·수면 패턴, 성장, 터미타임/상호작용, 접종 |
| 4~6개월 | 수면 변화, 발달, 뒤집기/운동, 이유식 준비 |
| 7~12개월 | 이유식/음식, 알레르기 기록, 이동 발달, 안전, 검진 |
| 12~24개월 | 식사, 언어·운동 발달, 놀이, 치아, 생활습관 |
| 2~5세 | 발달·언어, 놀이/학습, 생활습관, 기관 생활, 검진 |

**결론:** 하나의 고정 홈 화면에 모든 기능을 누적하는 것은 좋지 않다.

# 4. 기록 데이터의 우선순위

## Tier 1 — 자주 입력하며 즉각적인 가치가 큰 것
- 수유
- 수면
- 기저귀
- 약 실제 투여
- 체온/주요 증상

## Tier 2 — 자주 입력하지 않지만 장기 가치가 큰 것
- 성장
- 예방접종
- 건강검진
- 발달 마일스톤
- 음식 최초 노출/반응

## Tier 3 — 선택적 라이프로그
- 목욕
- 터미타임
- 산책
- 책읽기
- 놀이
- 사진/영상
- 첫 경험

모든 기록을 매일 요구해서는 안 된다.

# 5. 반드시 분리해야 하는 상태

- 예정 vs 완료
- 부모 관찰 vs 의료진 진단
- 정상적인 개인차 vs 위험 신호
- 정보 콘텐츠 vs 개인화된 판단
- 추정/예측 vs 실제 측정
- 자동 생성 데이터 vs 사용자가 직접 입력한 데이터

# 6. 좋은 육아 시스템의 8개 루프

## 6.1 Quick Capture Loop
`한 번 탭 → 기록 완료 → 최신 상태 즉시 갱신`

## 6.2 Caregiver Handoff Loop
`다른 양육자가 앱 열기 → 지금 상태 즉시 이해`

## 6.3 Pattern Loop
`일상 기록 → 하루/주간 패턴 → 변화 인지`

## 6.4 Reminder Loop
`예정 일정 → 알림 → 실제 완료 확인 → 다음 일정`

## 6.5 Growth Loop
`측정 → 추세 → 검진 시 공유`

## 6.6 Development Loop
`관찰 → 마일스톤 → 적절한 활동 → 다시 관찰`

## 6.7 Clinical Handoff Loop
`평소 기록 → 진료용 요약 → 의료진 상담 → 후속 기록`

## 6.8 Memory Loop
`일상 사진 → 자동 정리 → 회고 → 가족 공유 → 장기 보존`

# 7. 제품 설계에서 특히 중요한 원칙

1. **야간 사용을 기본 상황으로 본다.**
2. **한 손 사용을 기본으로 본다.**
3. 시작시각을 입력하면 종료시각 등은 최대한 자동화한다.
4. 최근 사용 항목을 우선 배치한다.
5. 입력 후 항상 현재 상태가 즉시 보이게 한다.
6. 매일 기록하지 않아도 죄책감을 유발하지 않는다.
7. 아이의 '점수'보다 추세와 관찰을 보여준다.
8. 데이터가 부족하면 예측의 신뢰도가 낮음을 드러낸다.
9. 알림은 많이 보내는 것이 아니라 **놓치면 비용이 큰 것**부터 보낸다.
10. 민감한 건강 데이터와 가족 사진의 공유권한을 별도로 설계한다.

# 8. 향후 분석 시 확인할 질문

각 앱에서 다음을 확인한다.

- 첫 화면에서 가장 큰 버튼은 무엇인가?
