# 아이사랑 — 페이지·UI·UX·버튼 지도

## 1. 월령별 육아 페이지

[A1]

1~3개월 화면에서 실제 확인되는 하위 메뉴:

```
1~3개월
├─ 성장발달
├─ 관계와 소통
├─ 행동
├─ 안전
├─ 수유
├─ 배설
├─ 수면
├─ 건강과 일상
└─ 놀이와 학습
```

다른 월령에서도 유사한 상위 taxonomy를 유지한다.

## 2. 콘텐츠 UI

공공정보 특성:
- 제목
- 소제목
- 표
- 자료원
- 긴 설명

으로 구성된다.

민간 앱처럼 카드 몇 개로 단순화하기보다 근거와 coverage를 우선한다.

## 3. 자료원 표시

성장 정보 등에서 질병관리청 성장도표 같은 출처를 명시한다.

좋은 UI 원칙:
- 출처
- 기준연도
- 적용 연령
- 마지막 검토일

을 사용자에게 숨기지 않는다.

## 4. 어린이집 탐색

공개 안내에서 부모가 실제 의사결정에 쓰는 속성들을 제공한다.

예:
- 위치
- 유형/특성
- 정원/현원
- 평가
- 통학차량

일반 지도검색보다 **보육 의사결정 속성** 중심이다.

## 5. 보육행정

포털/앱은 단순 정보를 넘어:
- 비용
- 지원
- 신청/조회
- 기관소통

등 실제 transaction으로 이어진다.

## 6. 가정통신문

아이의 생활이 가정 중심에서 기관 중심으로 바뀌면 "오늘 기록"보다 **기관이 보낸 정보 확인**이 중요해진다.

이 lifecycle 전환을 UI에도 반영해야 한다.

## 7. UX 장점

- 한 번 익힌 taxonomy를 월령이 바뀌어도 재사용
- 공공 source가 명확
- 행정행동까지 연결

## 8. UX 단점

- 긴 메뉴
- 정보량 과다
- 모바일에서 탐색 비용 가능성
- 개인 상태에 맞춘 우선순위가 약함
