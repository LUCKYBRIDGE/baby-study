웹은 네이티브 앱 기능보다 acquisition과 sleep education 역할이 강하다.

## 2. Hero UX

첫 약속은 "수면 기록" 자체가 아니라 **bedtime을 쉽게 만든다**는 결과 중심 메시지다.

이어지는 가치:
- personalized sleep plan
- soothing sounds
- 바로 적용 가능한 tips

## 3. 핵심 앱 화면의 정보 우선순위

공식 기능 설명을 기준으로 가장 중요한 Home 정보는 다음처럼 해석된다.

```
Next Nap / Bedtime
├─ 예상 시각
├─ 현재 wake window
├─ 준비 타이밍
└─ 오늘 실제 수면 흐름
```

그 아래:
- total sleep
- trend
- history

가 배치되는 것이 자연스럽다.

## 4. Tracking

핵심 action:
- sleep start
- sleep end
- 과거 수면 기록
- 다른 육아 기록

수면 vertical이므로 기록 자체보다 예측 모델 입력의 의미가 크다.

## 5. Prediction UI

좋은 수면 예측 UX는 단일 확정 시각보다:
- 예상 범위
- 최근 데이터 근거
- 실제 아이 신호 우선
- 틀렸을 때 즉시 수정

이 필요하다.

## 6. Education

Sleep Course / Blog는 앱 예측을 이해할 수 있게 해주는 설명층이다.

```
Generic education
→ personalized plan
```

이 순서가 좋다.

## 7. Pricing UX

무료:
- 기본 tracking
- age-based schedule

유료:
- 개인화 분석
- trend/stat
- 추가 content/tools

즉 유료벽은 **단순 기록이 아니라 개인화된 해석**에 위치한다.

## 8. 앱 밖 surface

공개 사이트 기준으로 lock-screen/watch의 구체 범위는 Huckleberry만큼 명확히 확인되지 않았다. [U]

따라서 네이티브 widget/notification은 설치 테스트가 필요하다.
