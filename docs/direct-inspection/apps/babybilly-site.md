# 베이비빌리 — 공식 사이트 직접 관찰

> 관찰일: 2026-11-08  
> 근거: BabyBilly 공식 한국 사이트  
> 레벨: A1

## 1. 실제 상위 내비게이션

공식 사이트에서 확인되는 주요 범주:
- 임신 준비
- 임신
- 육아
- 베동 모임
- 입점·광고

그리고 사이트 검색이 별도로 존재합니다.

이 구조 자체가 **콘텐츠 서비스 + 커뮤니티 + 커머스 플랫폼**임을 보여줍니다.

## 2. 핵심은 주수/월령 기반 orchestration

공식 사이트는 임신 주수와 아기 성장 단계에 따라:
- 필요한 검사
- 증상/건강
- 태아/아기 성장
- 준비물
- 부모 역할
- 음식
- 교육/놀이

등을 재배치합니다.

즉 콘텐츠 taxonomy보다 먼저:

```
Current Stage
→ Relevant Content
```

가 작동합니다.

## 3. 캐릭터/일러스트 기반 성장 표현

베이비빌리는 태아·아기 상태를 일러스트와 친근한 문장으로 전달합니다.

역할은 단순 장식보다 큽니다.
- 주수/월령 변화 시각화
- 매일 확인할 이유 제공
- 불안한 정보를 정서적으로 완화
- 서비스 전반 브랜드 일관성

다만 위험신호나 의료정보는 캐릭터 표현과 분리해 명확하게 제시해야 합니다.

## 4. 베동 커뮤니티

공식 메뉴 자체에 베동 모임이 독립되어 있습니다.

핵심은 일반 육아 커뮤니티가 아니라 **같은 시기의 부모**를 연결한다는 점입니다.

```
Pregnancy week / Baby age
→ Cohort
→ Questions / experiences
```

장점:
- 맥락 일치
- 공감도 높음
- 비슷한 검사/증상/준비 시기

위험:
- 같은 시기라는 이유로 개인차가 무시될 수 있음
- 경험담이 의료정보처럼 받아들여질 수 있음

## 5. 건강 기록

공식 페이지에서:
- 아기
- 엄마
- 체중
- 복부둘레
- 머리둘레

등의 기록과 평균범위/권고 비교를 제공합니다.

즉 콘텐츠만이 아니라:

```
General stage information
+
Personal measurement
```

을 결합합니다.

## 6. 커머스가 stage context를 사용

공식 사이트는 시기별 필요한 상품, 특가, 무료배송 등을 함께 노출합니다.

이는 단순 쇼핑몰 추천보다:

```
Life stage
→ upcoming need
→ product
```

구조입니다.

상업적으로 강하지만, 건강정보와 상품추천의 경계를 시각적으로 명확히 해야 합니다.

## 7. 제품의 실제 난점

베이비빌리 같은 슈퍼앱의 가장 큰 문제는 **홈 경쟁**입니다.

동시에 중요해 보이는 것:
- 오늘 콘텐츠
- 기록
- 커뮤니티
- 쇼핑
- 성장 정보

따라서 좋은 홈은 기능을 다 보여주는 것이 아니라 현재 시기/상태별로 우선순위를 조정해야 합니다.

## 8. 직접 관찰 핵심

베이비빌리를 분석할 때 "기능이 많다"가 핵심이 아닙니다.

가장 중요한 패턴:

**Age/Stage를 global router로 사용하여 콘텐츠·커뮤니티·건강기록·커머스를 동시에 조정한다.**
