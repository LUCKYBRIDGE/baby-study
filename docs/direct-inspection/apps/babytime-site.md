# BabyTime — 직접 사이트/FAQ 관찰

> 관찰일: 2026-11-08  
> 근거: 공식 홈페이지 + 공식 FAQ  
> 레벨: A1/A2

## 1. 실제 공식 홈페이지에서 전면에 둔 것

공식 홈페이지의 가치 제안은 다음 순서입니다.

1. **활동 기록**
2. **실시간 공동 기록**
3. **패턴 비주얼라이징**
4. **기간별 통계**
5. **성장/추억**
6. **또래 커뮤니티**

즉 브랜드 메시지부터 `Record → Analyze → Share` 순입니다.

## 2. 실제 기록 생성 흐름

FAQ에서 확인된 기록 입력 방식:

```
메인 기록 화면
→ 상단 활동 아이콘 탭
→ 탭과 동시에 활동 목록 생성
→ 생성된 목록을 탭
→ 상세 입력/수정
```

이 구조는 중요합니다.

일반 폼 UX:
```
아이콘 → 상세폼 → 저장 → 생성
```

BabyTime:
```
아이콘 → 즉시 생성 → 필요 시 상세 수정
```

즉 **event capture를 먼저 성공시키고 detail은 뒤로 미룹니다.**

### 적합한 이유
- 한 손 사용
- 수유/기저귀 중 즉시 기록
- 기록 누락 방지
- 수정은 나중에 가능

## 3. 시간형 이벤트 처리

모유수유·수면·목욕은 수정화면에서:
- 시작시간 기준
- 종료시간 기준
- 현재시간으로 종료

를 조정할 수 있습니다.

이는 이벤트 모델상:

```
start_at
end_at
duration
```

을 모두 사용하지만, 사용자가 **어느 기준시각을 고정할지 선택**하게 한 구조로 볼 수 있습니다.

## 4. 메인 기록 화면 커스터마이즈

FAQ에서:
- 활동 기록 아이콘 순서 재배치
- drag handle 사용

이 확인됩니다.

즉 기록 대상은 고정되어 있어도 **high-frequency action order는 사용자별로 바꿀 수 있습니다.**

월령 적응을 자동으로 하지 않아도:
- 신생아 → 수유/수면/기저귀
- 이유식기 → 식사/수면
- 유아기 → 병원/성장/생활

처럼 사용자가 홈을 재구성할 수 있습니다.

## 5. Pattern 화면

실제 FAQ에서는 Pattern 탭 안에 다시:
- 일과표
- 패턴

이 나뉩니다.

### 일과표
날짜를 좌우 이동하고, 활동 종류를 on/off 하여 보고 싶은 것만 표시.

### 패턴
특정 활동만 선택하면 **활동과 활동 사이 간격(interval)**을 표시.

즉 BabyTime은 단순 timeline보다 **inter-event interval**을 별도 1급 정보로 취급합니다.

육아에서 interval은 매우 중요합니다.
- 수유텀
- 수면 사이 깨시
- 배변 간격

## 6. 통계 화면

FAQ에서 확인:
- 그래프 추가/삭제
- 그래프 순서 이동
- 일/주/월 전환
- 표 좌우 스크롤로 최근 수치 비교

즉 Dashboard 자체도 사용자 구성형입니다.

```
Event
→ Aggregation
→ Chart Module
→ User-selected Dashboard
```

## 7. 커뮤니티 구조

커뮤니티는 일반 게시판이 아니라 **D+몇일** 기준으로 이동할 수 있습니다.

사용자는:
- 하루씩 이전/다음
- 특정 D+day 직접 입력

으로 또래 아기의 다이어리를 봅니다.

이는 매우 강한 **age-relative community** 구조입니다.

## 8. 다자녀 구조

FAQ에서:
- 프로필에서 아이 추가
- 메인 프로필 사진 롱탭으로 아이 전환
- 프로필 탭에서 이름 드롭다운으로 전환

이 확인됩니다.

즉 current child context를 전역 상태로 사용하는 구조입니다.

## 9. 성장 기록

성장 기록은 독립 기록 탭이 아니라:
```
Profile
→ Diary 작성
→ 성장 버튼
```
에서 입력하며, 별도 성장곡선에서 결과를 봅니다.

이는 생활기록과 성장기록의 UX가 서로 다른 도메인으로 취급됨을 보여줍니다.

## 10. 공동양육 연결 구조

공식 FAQ에서 실제 연결 과정:

```
Profile
→ 공동 양육자 초대
→ 관계 선택
   ├─ 엄마
   ├─ 아빠
   ├─ 베이비시터
   └─ 가족 멤버
→ 6자리 초대코드 생성
→ 상대가 10분 내 입력
→ 아이 연결
```

중요한 점:
- 공동양육자는 단순 동일 계정 로그인이 아님
- **관계(role label)**를 선택
- 아이를 중심으로 계정이 연결됨

Huckleberry의 동일계정 다기기 방식과 상당히 다릅니다.

## 11. 콘텐츠/공개권한

일기는 기본적으로 프로필 안에 있고, 사용자가 명시적으로:
`BabyTime 유저와 공유하기`
를 눌러 커뮤니티에 공개합니다.

즉:
- private diary
- public community

가 상태로 분리됩니다.

## 12. 직접 관찰로 수정된 기존 해석

기존에는 BabyTime 공동양육을 단순 "실시간 동기화"로만 봤지만 실제 FAQ를 보면:
- 관계 지정
- 초대코드
- child connection

구조가 있어 **Baby-centered shared workspace에 더 가깝습니다.**

또 Pattern은 단순 그래프가 아니라 **활동 간 간격 분석 도구**라는 점이 더 명확해졌습니다.
