# 대한민국 공공 육아·건강 시스템 — 직접 사이트/PDF 관찰

> 관찰일: 2026-11-08  
> 대상: 아이사랑, 질병관리청 예방접종도우미, 국민건강보험 영유아 건강검진  
> 레벨: A1/A2

# 1. 아이사랑

공식 포털은 크게 두 계층이 결합되어 있습니다.

## 육아 지식 계층

월령별로 반복되는 핵심 taxonomy:
- 성장발달
- 관계와 소통
- 행동
- 안전
- 수유/영양
- 배설
- 수면
- 건강과 일상
- 놀이와 학습

이 taxonomy는 월령이 바뀌어도 큰 틀이 유지되고 실제 내용만 바뀝니다.

따라서 구조는:

```
Stable Domain Taxonomy
+
Age-specific Content
```

입니다.

이는 민간 앱이 "무엇을 빠뜨렸는지" 점검할 coverage checklist로 가치가 큽니다.

## 보육 행정 계층

- 어린이집 검색
- 위치/시설특성
- 보육료
- 지원
- 가정통신문
- 상담

즉 아이사랑은 정보 사이트를 넘어 **기관 돌봄 단계로 넘어간 이후의 실제 행정**까지 다룹니다.

## 제품 시사점

아기가 성장하면 홈의 핵심 과업이:

```
가정 내 기록
→ 기관 선택
→ 기관과 소통
```

으로 이동합니다.

통합 육아 시스템이 2~5세까지 간다면 어린이집/유치원 관련 모듈을 뒤늦게 덧붙이는 것이 아니라 lifecycle transition으로 설계해야 합니다.

# 2. 예방접종도우미

공식 사이트의 핵심 구조:

```
예방접종 관리
├─ 아이 등록
├─ 접종내역
├─ 일정
└─ 알림

예방접종 정보
├─ 국가예방접종
├─ 백신별 정보
└─ 계절성 사업

Action
└─ 위탁의료기관 찾기
```

## 가장 중요한 점

예방접종은 단순 정적 달력이 아닙니다.

정책/백신/사업기간은 변경되므로 앱 데이터모델에는:

```
source_authority
source_version
reviewed_at
eligibility
dose
recommended_window
```

가 필요합니다.

## 예정과 실제를 분리

```
Official Schedule
≠
Child Actual Vaccination Record
```

이 분리가 없으면:
- 지연
- 예외
- 계절성 접종
- 이미 다른 기관에서 접종

을 제대로 처리할 수 없습니다.

## 알림도 별도 시스템

공식 체계는 개인 접종내역과 알림 동의를 연결합니다.

민간 앱은 단순:
> D-day 1

보다:
- 접종 가능 기간 시작
- 종료 임박
- 실제 완료 확인
- 다음 차수 계산

을 구분해야 합니다.

# 3. 영유아 건강검진

국민건강보험 공식 안내 PDF를 직접 확인했습니다.

## 공식 사용자 흐름

PDF의 "편리하게 받는 방법"에서 실제로:

```
1. 검진기관 찾기/예약
2. 웹(Web) 문진표 또는 발달선별검사지 작성
3. 검진
4. 결과
5. 이상소견 시 전문기관 의뢰
```

구조가 확인됩니다.

즉 검진 기능을 "날짜 알림" 하나로 축소하면 핵심 흐름의 대부분을 놓칩니다.

## 검진의 목적

공식 자료는 생후 14~71개월 성장 단계별 건강검진임을 설명하며 다음을 결합합니다.
- 문진/진찰
- 키/몸무게/머리둘레
- 발달평가/상담
- 건강교육

## 발달평가

3차 이후 주요 검진에서 검사도구에 의한 발달평가와 상담이 들어갑니다.

이 구조는:

```
Daily Observation
→ Official Screening
→ Clinical Evaluation if needed
```

으로 구분해야 합니다.

민간 milestone tracker 결과를 K-DST나 의료진 판단과 같은 데이터로 저장해서는 안 됩니다.

## 검진 전 웹 문진

공식 안내는 특정 시점부터 웹 문진/발달선별검사지 작성을 지원합니다.

민간 육아 앱이 할 수 있는 좋은 역할:

```
평소 기록
→ 검진 전 질문/요약
→ 공식 문진으로 연결
```

공식 문진을 자체적으로 대체하는 것이 아니라 **준비를 보조**합니다.

## 결과 후 referral

공식 PDF에는 이상소견에 따라:
- 소아청소년과
- 안과
- 이비인후과
- 발달 전문기관 등

의뢰 예시가 제시됩니다.

따라서 좋은 앱은 결과를 보관하고 끝내지 않고:

```
Result
→ Follow-up task
→ Specialist appointment
→ Next observation
```

로 이어져야 합니다.

## 건강교육이 부모 커리큘럼 역할

공식 자료에서 시기별 건강교육은:
- 안전사고 예방
- 수면
- 구강
- 대소변 가리기
- 전자미디어
- 정서/사회성
- 개인위생
- 취학 준비

등으로 확장됩니다.

이는 한국 영유아 부모에게 시기별로 제공할 **공식 부모교육 curriculum**의 좋은 기준입니다.

# 4. 세 공공 시스템의 역할 분담

```
아이사랑
= 월령별 육아정보 + 보육기관/행정

예방접종도우미
= 공식 접종 규칙 + 개인 이력 + 기관

NHIS 건강검진
= 공식 성장/발달 screening + 결과 + referral
```

통합 민간 앱은 이들을 복제해서는 안 됩니다.

더 좋은 구조:

```
Parent-friendly UX
↓
Official Source
↓
Deep Link / Eligibility
↓
Official Transaction / Healthcare
```

즉 공공 시스템은 **authoritative backend/reference**로 활용하고, 민간 앱은 사용자가 이해하고 준비하는 레이어를 담당하는 편이 안전합니다.
